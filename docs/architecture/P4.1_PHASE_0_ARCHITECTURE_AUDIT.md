## Independent Prayer Alarms & Multiple Adhan Sounds

**المشروع:** تطبيق حافظ العهد (Hafiz Al-Ahd)  
**المرحلة:** P4.1 — Phase 0: Architecture Audit (READ-ONLY)  
**الجهاز المستهدف:** Xiaomi 25098RA98G — Android 16 / API 36  
**التاريخ:** 07/11/2026  
**الحالة:** تدقيق معماري للقراءة فقط — ممنوع إجراء تعديلات كودية (STOP GATE)

## 1. ملخص تنفيذي (Executive Summary)

يهدف مشروع **P4.1** إلى تمكين المستخدم من التحكم المستقل في منبه/إشعار كل صلاة على حدة (الفجر، الظهر، العصر، المغرب، العشاء)، مع إمكانية تخصيص صوت الأذان لكل صلاة، بما في ذلك استيراد ملفات صوتية مخصصة من ذاكرة الجهاز.

تم إجراء تدقيق معماري شامل وشديد التدقيق لكامل البنية التحتية البرمجية الخاصة بحساب المواقيت، الجدولة، خدمات أندرويد الأصلية (Native Services / MethodChannels)، دورة حياة الأذان، الصلاحيات، والتخزين المحلي.

النتيجة الأساسية للتدقيق:
- البنية الحالية مستقرة للغاية في حساب المواقيت وتجاوز قيود نظام أندرويد (Doze Mode & Screen Lock).
- ومع ذلك، **تعتمد بنية الجدولة الحالية على إعداد عالمي واحد (`adhanStyle`) لجميع الصلوات الخمس معاً**، ومسارات الأصوات **مكتوبة بشكل ثابت (Hardcoded)** داخل كود الجدولة.
- يمكن تحقيق المتطلبات الجديدة بالكامل دون إعادة كتابة جذرية للمحرك، وذلك عبر **استحداث طبقة تكوين مستقلة لكل صلاة (Per-Prayer Alarm Configuration)** و **تجريد لمصادر الصوت (Adhan Audio Source Abstraction)** مدمجة بسلاسة مع `ScheduleWeeklyPrayersUseCase` و `package:alarm`.

## 2. نتائج الفحص والتدقيق التفصيلي (Detailed Audit Findings)

### 2.1 حساب مواقيت الصلاة وإدارة الحالة (Prayer-Time Calculation & State Management)
* **محرك الحساب الفلكي:** يعتمد على مكتبة `adhan_dart: ^2.0.1` داخل `PrayerTimesLocalDataSource`. الحساب دقيق ويعمل بتوقيت UTC ويتم تحويله إلى التوقيت المحلي عبر مكتبة `timezone: ^0.11.0`.
* **معالجة الدول والاستثناءات:** يتولى `CalculationMethodHelper` كشف الدولة بناءً على الإحداثيات الجغرافية أو الكاش وتطبيق طرق الحساب الرسمية (مثل تقويم أم القرى، وزارة الأوقاف بالمغرب مع دقائق الاحتياط، وغيرها).
* **إزاحات الدقائق و DST:** تُطبق إزاحات التوقيت الصيفي (`applyDstOffset`) وإزاحات الدقائق المخصصة لكل صلاة (`applyOffsets`) بسلاسة لإنتاج `PrayerTimesEntity`.
* **إدارة الحالة:** `PrayerTimesCubit` يدير جلب المواقيت وتحديث العداد الثابت (`Sticky Notification`) والجدولة الأسبوعية.
* **الاستقرار والتحديث الذاتي:**
  - `TimeCubit` يعمل بمؤقت دوري كل ثانية، وعند حلول منتصف الليل (`now.day != _lastDay`) يستدعي `loadPrayerTimesFromCache()` لتحديث مواقيت اليوم الجديد تلقائياً.
  - `checkTimezoneOffsetChange()` يرصد أي تغيير في فارق التوقيت المحلي (مثل ليلة تغيير التوقيت الصيفي/الشتوي) ويستدعي `forceReschedule()`.

### 2.2 بنية جدولة المنبهات الحالية (Alarm Scheduling Implementation)
* **المسؤول عن الجدولة:** كلاس `ScheduleWeeklyPrayersUseCase` في `lib/features/notifications/domain/usecases/schedule_weekly_prayers_usecase.dart`.
* **الأفق الزمني للجدولة:** 5 أيام قادمة (`for (int i = 0; i < 5; i++)`).
* **منع التضارب وحماية المعالج:**
  - `_scheduleSessionId`: عداد جلسات ذري (Atomic Session Counter) يلغي أي جلسة جدولة قديمة إذا بدأت جلسة أحدث.
  - `Throttling / Chunking`: تأخير بمقدار 150 مللي ثانية بين كل يوم والآخر لمنع تجمد خيط الواجهة (UI Lag) ومنع إرهاق خيط أندرويد الأصلي بطلبات `PendingIntent` مكثفة.
* **آلية التطهير قبل الجدولة:**
  - يتم استدعاء `notificationRepository.cancelAllAlarms()` (عبر `Alarm.stopAll()`) و `cancelActivePrayerNotification()` لمسح المنبهات القديمة قبل وضع الجديدة، مما يمنع تراكم المنبهات أو تكرارها.
* **نقطة القصور الحالية (Current Limitation):**
  - الكود يفحص متغيراً واحداً فقط: `adhanStyle = pref.getString('adhanStyle') ?? 'alarm'`.
  - إذا كان `adhanStyle == 'alarm'`، يُجدول منبه كامل الشاشة لجميع الصلوات.
  - إذا كان `adhanStyle == 'notification'`، يُجدول إشعار بسيط لجميع الصلوات.
  - إذا كان `adhanStyle == 'none'`، يُلغى التنبيه تماماً لجميع الصلوات.
  - الأصوات ثابتة: الفجر دائماً `assets/sounds/fajr_azan.mp3`، وباقي الصلوات دائماً `assets/sounds/adhan.mp3`.

### 2.3 مكونات أندرويد الأصلية وقنوات الاتصال (Android Native Components & MethodChannels)
* **القناة الرئيسية:** `com.shadyatef.hafiz_alahd/alarm_channel` في `MainActivity.kt` و `NativeAlarmService.dart`.
* **الوظائف المدعومة:**
  1. `scheduleExactAlarm`: يجدول منبهاً دقيقاً عبر `AlarmManager.setExactAndAllowWhileIdle` موجه إلى `PrayerUpdateReceiver` مع بيانات الصلاة القادمة. الهدف منه هو تحديث بيانات الودجت في الشاشة الرئيسية والعداد التنازلي للإشعار الثابت فورياً دون إيقاظ محرك Flutter (Zero Dart VM Overhead).
  2. `getDisplayRefreshRate`: استعلام عن معدلات التحديث للشاشة.
* **المستقبلات والخدمات المصرح بها في `AndroidManifest.xml`:**
  - `PrayerUpdateReceiver`: يستقبل بث المنبه الدقيق الأصلي، ويحدث `HomeWidget` و `sticky_countdown_channel_v1`.
  - `PrayerWidgetProvider`: مزود ودجت الشاشة الرئيسية.
  - `BackgroundService` (`id.flutter.flutter_background_service.BackgroundService`): خدمة أمامية مخصصة للعداد الثابت المستمر.
  - حزمة `package:alarm`: تعتمد على `AlarmService` كخدمة أمامية أصلية مدمجة مع `MediaPlayer` لتشغيل الصوت وفتح الشاشة عند الإغلاق.

### 2.4 دورة حياة تشغيل وإيقاف الأذان (Adhan Playback Lifecycle)
* **لحظة انطلاق المنبه:**
  1. يطلق نظام أندرويد `AlarmManager` المنبه المحدد بدقة متجاوزاً وضع الخمول (Doze Mode).
  2. تبدأ حزمة `alarm` خدمتها الأمامية وتشغل ملف الصوت عبر `MediaPlayer`.
  3. بفضل `androidFullScreenIntent: true` وخصائص `MainActivity` (`setShowWhenLocked`, `setTurnScreenOn`, `requestDismissKeyguard`) تضاء الشاشة وتظهر فوق شاشة القفل.
  4. في بيئة Dart: يستقبل `Alarm.ringing.listen` (أو فحص البداية الباردة `Alarm.getAlarms()`) الحدث ويفتح `AdhanScreen`.
* **الإغلاق التلقائي واليدوي في `AdhanScreen`:**
  - سحب الزر (SliderButton): يستدعي `Alarm.stop(id)` لإيقاف الصوت والخدمة وإغلاق الشاشة.
  - مؤقت الإغلاق التلقائي (`_setupDynamicCloseTimer`): يقيس مدة الصوت بدقة عبر `audioplayers`، ويضبط مؤقتاً لإغلاق الشاشة وإيقاف المنبه تلقائياً بعد انتهاء الصوت بـ 5 ثوانٍ.
  - ضغط زر الباور / النزول للخلفية: ترصده `didChangeAppLifecycleState` (`paused` / `hidden`) وتوقف الأذان فوراً.
  - إيقاف من الإشعار الخارجي: تايمر دوري يفحص `Alarm.isRinging(id)` كل ثانيتين، وإذا أوقفه المستخدم من زر "إيقاف الأذان" في الإشعار، تُغلق الشاشة فوراً.
  - منع التراكم (Stacking Guard): إذا كان الهاتف مغلقاً لساعات وتراكمت منبهات، يتم إيقاف المنبهات القديمة ويُشغل فقط المنبه الأحدث إذا لم يمر عليه أكثر من 5 دقائق.

### 2.5 إدارة الإشعارات والصلاحيات (Notifications & Permissions)
* **صلاحيات أندرويد الحرجة المصرح بها:**
  - `SCHEDULE_EXACT_ALARM` و `USE_EXACT_ALARM`: لجدولة المنبهات الدقيقة (Android 12+).
  - `POST_NOTIFICATIONS`: لإظهار الإشعارات (Android 13+).
  - `USE_FULL_SCREEN_INTENT`: لفتح شاشة الأذان فوق شاشة القفل (Android 14+).
  - `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`: لحماية التطبيق من القتل في وضع Doze.
  - `FOREGROUND_SERVICE` و `FOREGROUND_SERVICE_MEDIA_PLAYBACK`: لتشغيل الصوت في الخلفية دون انقطاع.
  - `READ_EXTERNAL_STORAGE`: موجود، ولكن في نظام أندرويد 13+ (API 33+) نحتاج التأكد من استدعاء منتقي الملفات النظامي (Storage Access Framework) أو استخدام مسار التطبيق الخاص لنسخ الملفات دون الحاجة لصلاحية التخزين الواسعة المرفوضة في متجر جوجل بلاي.
* **قنوات الإشعارات:**
  - `sticky_countdown_channel_v1`: إشعار العداد الثابت (Importance.low).
  - `prayer_channel_v10_$soundName`: إشعارات الأذان العادية بصوت مخصص (Importance.max).

### 2.6 بنية التخزين وقواعد البيانات الحالية (Persistence Architecture)
* **المستودع الرئيسي:** `SharedPreferences` (LazySingleton مسجل في `service_locator.dart`).
* **المفاتيح الحالية:**
  - مفاتيح إعدادات عامة: `adhanStyle`, `adhan_volume`, `isAdhanVibrationEnabled`, `isIqamaEnabled`, `isAzkarReminderEnabled`.
  - مفاتيح التوقيت: `calculation_method`, `madhab`, `custom_fajr_angle`, `custom_isha_angle`, `dst_offset_minutes`.
  - مفاتيح إزاحات الصلوات: `prayer_offset_fajr`, `prayer_offset_dhuhr`, ... إلخ.
  - مفاتيح كاش الجدولة: `scheduled_until_date`, `last_known_timezone_offset_minutes`, `CACHED_LOCATION`.
* **الغياب الحالي:**
  - لا يوجد كيان (Entity) أو نموذج (Model) يمثل `PrayerAlarmConfig`.
  - لا توجد طبقة لإدارة ملفات الصوت المخصصة وقائمتها ومساراتها المحلية.

### 2.7 سلوك المنبهات تحت الظروف والبيئات المختلفة (Lifecycle Resilience)
1. **إنهاء التطبيق (Swiped from Recents / Terminated):**
   - يعمل بثبات تام بفضل `androidStopAlarmOnTermination: false`؛ حيث تظل المنبهات مسجلة في `AlarmManager` على مستوى نظام التشغيل وتوقظ الجهاز عند الموعد.
2. **إعادة تشغيل الجهاز (Device Reboot):**
   - مدعوم عبر `RECEIVE_BOOT_COMPLETED` ومستقبلات حزمة `alarm`؛ وعند فتح التطبيق يتم التحقق وإعادة الجدولة إذا لزم الأمر.
3. **وضع السكون وتوفير الطاقة (Doze Mode):**
   - محمي عبر `setExactAndAllowWhileIdle` واستثناء تحسين البطارية.
4. **تغيير مواقيت الصلاة (تغيير الموقع أو طريقة الحساب):**
   - مستقر ومجرب؛ يستدعي `forceReschedule()` فوراً لمسح القديم وجدولة الجديد.
5. **تغير التوقيت الصيفي / فرق المنطقة الزمنية (Timezone / DST Change):**
   - محمي بواسطة `DST Guard`؛ يرصد فرق الدقائق ويعيد الجدولة في صمت.
6. **سحب الصلاحيات (Permission Revocation):**
   - كود `MainActivity.kt` يحتوي على حماية `try-catch (SecurityException)` تحول المنبه الدقيق إلى منبه غير دقيق لمنع كراش التطبيق لو سُحبت الصلاحية من إعدادات النظام.

## 3. تحليل المكونات: ما يُعاد استخدامه وما يتطلب التعديل

### 3.1 مكونات يُعاد استخدامها بالكامل دون مساس (Preserve As-Is)
1. `PrayerTimesLocalDataSource` و `GetPrayerTimesUseCase` و `CalculationMethodHelper`: حساب المواقيت الفلكية سليم ومكتمل بنسبة 100%.
2. `TimeCubit` و `PrayerUpdateReceiver` و `MainActivity.kt` MethodChannel: مزامنة الوقت والودجت والعداد الثابت تعمل بكفاءة.
3. `BackgroundServiceManager` و `PrayerWidgetProvider`: إدارة الإشعار المستمر والودجت لا تتأثر.
4. `AdhanScreen`: واجهة تشغيل الأذان وإيقافه متكاملة وتدعم مؤقت الصوت الديناميكي.

### 3.2 مكونات تتطلب التعديل أو التوسيع (Require Modification)
1. `ScheduleWeeklyPrayersUseCase`:
   - تحويل القراءة من المتغير العام `adhanStyle` إلى استهلاك تكوين كل صلاة على حدة (`PrayerAlarmConfig`).
   - استبدال مسار الصوت الثابت (`assets/sounds/adhan.mp3`) بالصوت المخصص لتلك الصلاة من التكوين المحفوظ.
2. `NotificationRepositoryImpl`:
   - دعم تمرير مسارات ملفات داخلية (`FileSource`) بالإضافة لمسارات الأصول (`AssetSource`).
3. `SettingsScreen`:
   - إعادة تصميم قسم الأذان لعرض بطاقة لكل صلاة من الصلوات الخمس مع خيارات التنبيه (منبه كامل الشاشة، إشعار، صامت، إيقاف) واسم الصوت المختار وزر لاختياره.
4. `SharedPreferences` / Data Layer:
   - إنشاء Data Source ومستودع لإدارة تكوينات الصلوات وقائمة الأصوات المتاحة والمستوردة.

### 3.3 مكونات جديدة يلزم إنشاؤها (New Components to Create)
1. `PrayerAlarmConfig`: كائن كيان يمثل إعدادات صلاة معينة (نوع التنبيه: alarm / notification / vibrate_only / silent / off، ومصدر الصوت).
2. `AdhanAudioSource`: كائن مجرد يمثل مصدر صوت الأذان (مدمج Asset، أو مستورد File، مع بيانات المعرف والاسم المعروض ومدة الصوت).
3. `AdhanAudioRepository`: مستودع لإدارة الأصوات المدمجة، استيراد وفحص وحفظ ملفات المستخدم الصوتية، وحذفها بأمان.
4. `AdhanAudioPickerBottomSheet / Dialog`: واجهة منبثقة أنيقة لاستعراض الأصوات، تشغيل ومعاينة الصوت (Preview Player)، واختياره أو استيراد ملف جديد.

### 5.1 نموذج بيانات تكوين صلاة مستقلة (PrayerAlarmConfig)

## 6. متطلبات التهجير والتوافقية الرجعية (Migration Requirements)

لضمان عدم تأثر أي مستخدم حالي عند التحديث:
1. عند أول إقلاع بعد التحديث: يتم فحص إعداد `adhanStyle` القديم:
   - إذا كان `'alarm'`: يتم تهيئة جميع الصلوات الخمس بـ `PrayerAlarmType.alarm`.
   - إذا كان `'notification'`: يتم تهيئة جميع الصلوات بـ `PrayerAlarmType.notification`.
   - إذا كان `'none'`: يتم تهيئة جميع الصلوات بـ `PrayerAlarmType.off`.
2. يتم تعيين الصوت الافتراضي لصلاة الفجر: الصوت المدمج الخاص بالفجر (`fajr_azan`).
3. يتم تعيين الصوت الافتراضي لباقي الصلوات: الصوت المدمج العام (`default_adhan`).
4. يتم استيراد قيم الصوت والاهتزاز العامة كقيم افتراضية للصلوات الخمس.
5. استدعاء `forceReschedule()` لمرة واحدة لجدولة المنبهات وفق البنية الجديدة بسلاسة ودون تكرار.

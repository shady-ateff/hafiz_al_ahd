## 1. Classification & Typology Standards

To preserve architectural precision, all tests in this inventory are strictly categorized according to execution reality:
- **Pure Unit Test:** Executes in-memory Dart algorithms (e.g. ID calculation, boundary math, validation) with zero I/O or plugin involvement.
- **Fake Contract Test:** Executes domain logic against in-memory controlled test doubles (`ControllableNotificationRepository`, `FakePrayerAlarmConfigRepository`), validating state transitions and contracts.
- **Production Integration Test:** Directly instantiates and invokes production use case code (`ScheduleWeeklyPrayersUseCase.execute()`), verifying integration between production components.
- **Package Behavior Test:** Verifies third-party library constraints or mocks platform channels.
- **Physical Device / Instrumentation Verification:** Required for Android OS hardware-level validation (`AlarmManager`, `MediaPlayer`, OEM battery restrictions, physical reboot).

## 4. Fundamental Testing Boundary Disclaimer

> ⚠️ **ARCHITECTURAL MANDATE: FAKE TESTS DO NOT PROVE NATIVE ANDROID OS BEHAVIOR**
>
> All Fake-based tests (`ControllableNotificationRepository`) validate **Dart domain logic, transition sequencing, and mathematical invariants**. They **DO NOT and CANNOT** prove:
> 1. Native Android `AlarmManager` IPC execution.
> 2. `MediaPlayer` audio decoding and hardware wake locks in Android's `AudioServer`.
> 3. Xiaomi MIUI/HyperOS aggressive battery killer behavior in deep doze.
> 4. Physical device reboot survival.
>
> Therefore, formal sign-off for release requires **Phase 2D Physical Device Verification** on the user's Xiaomi 25098RA98G (Android 16 / API 36).

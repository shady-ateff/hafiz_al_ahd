## 1. Executive Summary

تهدف هذه المرحلة إلى توثيق الحالة الهندسية الدقيقة لكود الإنتاج (`lib/`)، ومستودعات الإعدادات، واستدعاءات الـ Scheduler القديم، ونتائج الاختبارات الأساسية، **قبل كتابة أو تعديل أي سطر في Production Code**.

## 2. فحص ملفات الإنتاج المستهدفة (Target Files Audit)

### 2.1. `BaseNotificationRepository`
- **المسار:** `lib/features/notifications/domain/repos/base_notification_repository.dart`
- **الحالة الحالية:**
  - يحتوي على `scheduleAdhanAlarm` و `cancelAllAlarms` و `cancelNotification` و `cancelActivePrayerNotification`.
  - **يفتقر حالياً إلى:** دالة الإلغاء المستهدف الآمن `Future<bool> cancelAlarmSafely(int id, {DateTime? expectedScheduledTime, String? expectedAssetAudioPath});`.
  - سيتم إضافة هذا التوقيع في **Phase 2C.1**.

### 2.2. `NotificationRepositoryImpl`
- **المسار:** `lib/features/notifications/data/repos/notification_repository_impl.dart`
- **الحالة الحالية:**
  - `cancelAllAlarms()` تستدعي مباشرة `await Alarm.stopAll();` (المسح الشامل الذي يقطع أي أذان نشط).
  - `cancelActivePrayerNotification()` تبحث في الإشعار ذي المعرف `active.id`.
  - `cancelAlarmSafely` **غير موجودة بعد**؛ سيتم تنفيذها في **Phase 2C.1** وفق منظومة التحقق الـ Fail-Closed.

### 2.3. `ScheduleWeeklyPrayersUseCase`
- **المسار:** `lib/features/notifications/domain/usecases/schedule_weekly_prayers_usecase.dart`
- **الحالة الحالية وتحليل السلوك القديم:**
  1. **المسح الشامل:** يستدعي في السطر 43-44:
     ```dart
     await notificationRepository.cancelAllAlarms();
     await notificationRepository.cancelActivePrayerNotification();
     ```
     مما يؤدي لمسح جميع التنبيهات وإيقاف الأذان النشط إن وُجد.
  2. **غياب الإعدادات المستقلة:** يعتمد على إعداد عام واحد:
     ```dart
     final adhanStyle = pref.getString('adhanStyle') ?? 'alarm';
     ```
     ولا يحقن أو يستعلم عن `BasePrayerAlarmConfigRepository`.
  3. **المعرفات التسلسلية:** يبدأ بـ `int notificationId = 1;` ويزيد تصاعدياً `currentId++` مسبباً تداخلاً بين الأيام والمواقيت وميزات الإقامة والأذكار.
  4. **خرق عقد الأفق المتصل (`scheduled_until_date`):**
     الأسطر 58-66 تتجاهل نتيجة فشل اليوم:
     ```dart
     final result = await getPrayerTimesUseCase(...);
     await result.fold((_) async {}, (prayerTimes) async { ... });
     ```
     ثم في السطر 89-91 يكتب عشوائياً:
     ```dart
     final newTargetDate = DateTime.now().add(const Duration(days: 5));
     await pref.setString('scheduled_until_date', newTargetDate.toIso8601String());
     ```
     حتى لو فشل اليوم الأول (Day 0)، مما يفسر فشل الاختبارات الـ 6 في Group A حالياً كجزء من منهجية Test-First.

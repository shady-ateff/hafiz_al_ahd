## 3. فحص بيئة نظام أندرويد وتداخل الحزم (Android System Namespace Inspection)

> [!CRITICAL]
> **حقيقة هندسية حاسمة على نظام Android:**  
> - `package:alarm` تستخدم `PendingIntent.getBroadcast(..., requestCode: id, ...)` ثم تعرض إشعار كامل الشاشة عبر `NotificationManager.notify(id, notification)`.  
> - `flutter_local_notifications` تستخدم أيضاً `AlarmManager` و `NotificationManager.notify(tag, id, notification)`.  
> - **كلا الحزمتين تعملان داخل نفس الـ Android Application Process (`context.packageName`) وتشتركان في نفس جدول الـ `NotificationManager` ونفس فضاء الـ `requestCode`!**  
> - إذا استُخدم نفس الـ ID بين Alarm و Notification، سيحدث **تداخل واستبدال فوري (Overwriting / Collision)** على مستوى نظام التشغيل!

### النتيجة المعمارية:
استخدام إزاحات مختلفة (`typeOffset: 0` للمنبه و `1` للإشعار و `2` للإقامة و `3` للأذكار) يضمن **فضاء معرفات فريد ومستقل 100% (Zero OS-Level Collision)** عبر جميع أحداث التطبيق، ويمنع أي تصادم بين الحزم أو الخدمات المحجوزة.

## 4. الصيغة الحسابية المعتمدة وحدود النطاق (Approved Formula & Boundaries)

### 4.1. الصيغة الحسابية
$$\text{ID} = (\text{year} \pmod{100}) \times 1,000,000 + \text{month} \times 10,000 + \text{day} \times 100 + \text{prayerIndex} \times 10 + \text{typeOffset}$$

### 4.2. فهرس الصلوات (`prayerIndex`)
| الصلاة (`PrayerId`) | الفهرس (`prayerIndex`) | ملاحظة |
|---|:---:|---|
| `fajr` | `0` | صلاة الفجر المفروضة |
| `dhuhr` | `1` | صلاة الظهر المفروضة |
| `asr` | `2` | صلاة العصر المفروضة |
| `maghrib` | `3` | صلاة المغرب المفروضة |
| `isha` | `4` | صلاة العشاء المفروضة |

*(صلاة الشروق `shurooq` خارج نطاق الجدولة والهوية الحسابية)*.

### 4.3. إزاحة الأنواع (`typeOffset`)
| نوع الحدث (Event Type) | الإزاحة (`Offset`) | نطاق المعرفات |
|---|:---:|---|
| **Prayer Alarm** | `0` | منبه الأذان كامل الشاشة |
| **Prayer Notification** | `1` | إشعار الأذان البسيط |
| **Iqama Notification** | `2` | إشعار الإقامة المرتبط بالصلاة |
| **Post-prayer Azkar** | `3` | أذكار ما بعد الصلاة |
| **Morning Azkar** | `4` | أذكار الصباح (مرتبطة بفهرس الفجر 0) |
| **Evening Azkar** | `5` | أذكار المساء (مرتبطة بفهرس العصر 2) |
| **Reserved Offsets** | `6 .. 9` | محجوزة للتوسعات المستقبلية |

### 4.4. حدود النطاق الزمني والـ 32-bit Integer
- **السنوات المدعومة:** `2024` إلى `2099`.
- **الحد الأدنى للمعرف الصالح:** `24010100` (1 يناير 2024 - الفجر منبه).
- **الحد الأقصى للمعرف الصالح:** `99123149` (31 ديسمبر 2099 - العشاء أقصى إزاحة).
- **التوافق مع أندرويد:** أقصى معرف (`99,123,149`) أقل بكثير من الحد الأقصى للأعداد الصحيحة 32-بت (`2,147,483,647`).

## 5. حسم الأسئلة السبعة لمراجعة التصميم (Design Review Resolutions)

### س1: هل `DateTime` يمثل Local Calendar Date أم UTC؟
- **القرار:** **Local Calendar Date**.
- **التعليل:** مواقيت الصلاة أحداث فلكية وجغرافية مرتبطة باليوم التقويمي المحلي للمستخدم. استخدام UTC يسبب انزياح اليوم (Date Drift) في المناطق ذات الفروق الزمنية (+3 أو -5)، مما يغير هوية اليوم.

### س2: هل نستخدم `DateTime(year, month, day)` كـ Date Identity؟
- **القرار:** **نعم**.
- **التعليل:** تجريد التوقيت من الساعات والدقائق والثواني يضمن أن أي كائن `DateTime` يشير إلى نفس اليوم المحلي ينتج نفس الهوية بدقة واستقرار تام.

### س3: هل `PrayerId` هو المصدر الوحيد للـ Prayer Index؟
- **القرار:** **نعم**.
- **التعليل:** يمنع استخدام الأرقام السحرية (Magic Numbers) ويضمن نوعية البيانات وحصر الفهارس بين 0 و 4.

### س4: كيف نرفض `PrayerAlertDecision.none` داخل `prayerAlertId()`؟
- **القرار:** **رمي `ArgumentError` صريح ومحدد (Fail-Closed).**
- **التعليل:** القاعدة 12 تنص على أن `off` لا ينتج معرف تنبيه. محاولة توليد ID لـ `none` يعتبر خطأ برمجي يجب إيقافه فوراً لمنع إنشاء معرفات وهمية.

### س5: هل نستخدم Exception واضحة أم Result Type؟
- **القرار:** **`ArgumentError` / `RangeError` (Exceptions صريحة).**
- **التعليل:** دالة توليد المعرف هي عملية رياضية نقية سريعة ومتزامنة (Synchronous Pure Function)، والأخطاء فيها هي انتهاك لشروط المدخلات (Preconditions).

### س6: هل نحتاج Generic `_computeId()` داخلياً لتقليل التكرار؟
- **القرار:** **نعم، دالة محرك خاصة `_computeId(...)` مركزية للتحقق والحساب، مع واجهة عامة Typed بالكامل.**

### س7: هل الـ API العامة يجب أن تكون Typed بالكامل أم تسمح بـ offsets؟
- **القرار:** **Typed بالكامل في الدوال العامة.**
- **التعليل:** منع تمرير أرقام عشوائية، وتوفير دوال متخصصة:
  - `prayerAlertId(date, prayer, decision)`
  - `iqamaId(date, prayer)`
  - `postPrayerAzkarId(date, prayer)`
  - `morningAzkarId(date)`
  - `eveningAzkarId(date)`
  *(مع إتاحة `computeRawId` تحت `@visibleForTesting` لاختبارات الحدود والإزاحات المحجوزة)*.

## 6. التصميم البرمجي المقترح (Proposed Class API)

الملف المستهدف: [`lib/features/notifications/domain/entities/calendar_alarm_id_contract.dart`](file:///c:/Users/shady%20atef/Documents/projects/hafiz_al_ahd/lib/features/notifications/domain/entities/calendar_alarm_id_contract.dart)

```dart
import 'package:flutter/foundation.dart';
import 'package:hafiz_al_ahd/features/notifications/domain/entities/prayer_alarm_config.dart';
import 'package:hafiz_al_ahd/features/notifications/domain/entities/prayer_scheduling_decision.dart';

/// Contract providing deterministic 32-bit calendar-based IDs for all scheduled events.
class CalendarAlarmIdContract {
  static const int minYear = 2024;
  static const int maxYear = 2099;
  static const int minValidId = 24010100;
  static const int maxValidId = 99123149;

  static const int offsetPrayerAlarm = 0;
  static const int offsetPrayerNotification = 1;
  static const int offsetIqama = 2;
  static const int offsetPostPrayerAzkar = 3;
  static const int offsetMorningAzkar = 4;
  static const int offsetEveningAzkar = 5;

  static const int reservedTestAlarmId = 888;
  static const int reservedHomeWidgetId = 999;
  static const int reservedForegroundServiceId = 8888;

  static const Set<int> reservedIds = {
    reservedTestAlarmId,
    reservedHomeWidgetId,
    reservedForegroundServiceId,
  };

  /// Generates the deterministic ID for a prayer alert based on its decision.
  static int prayerAlertId({
    required DateTime date,
    required PrayerId prayer,
    required PrayerAlertDecision decision,
  }) {
    final offset = switch (decision) {
      PrayerAlertDecision.alarm => offsetPrayerAlarm,
      PrayerAlertDecision.notification => offsetPrayerNotification,
      PrayerAlertDecision.none => throw ArgumentError.value(
          decision,
          'decision',
          'PrayerAlertDecision.none does not produce a prayer alert ID',
        ),
    };
    return _computeId(date: date, prayerIdx: prayerIndex(prayer), typeOffset: offset);
  }

  /// Generates the deterministic ID for an Iqama notification.
  static int iqamaId({required DateTime date, required PrayerId prayer}) {
    return _computeId(date: date, prayerIdx: prayerIndex(prayer), typeOffset: offsetIqama);
  }

  /// Generates the deterministic ID for post-prayer Azkar.
  static int postPrayerAzkarId({required DateTime date, required PrayerId prayer}) {
    return _computeId(date: date, prayerIdx: prayerIndex(prayer), typeOffset: offsetPostPrayerAzkar);
  }

  /// Generates the deterministic ID for Morning Azkar (linked to Fajr: index 0).
  static int morningAzkarId({required DateTime date}) {
    return _computeId(date: date, prayerIdx: prayerIndex(PrayerId.fajr), typeOffset: offsetMorningAzkar);
  }

  /// Generates the deterministic ID for Evening Azkar (linked to Asr: index 2).
  static int eveningAzkarId({required DateTime date}) {
    return _computeId(date: date, prayerIdx: prayerIndex(PrayerId.asr), typeOffset: offsetEveningAzkar);
  }

  static int prayerIndex(PrayerId prayer) {
    return switch (prayer) {
      PrayerId.fajr => 0,
      PrayerId.dhuhr => 1,
      PrayerId.asr => 2,
      PrayerId.maghrib => 3,
      PrayerId.isha => 4,
    };
  }

  @visibleForTesting
  static int computeRawId({required DateTime date, required int prayerIdx, required int typeOffset}) {
    return _computeId(date: date, prayerIdx: prayerIdx, typeOffset: typeOffset);
  }

  static int _computeId({required DateTime date, required int prayerIdx, required int typeOffset}) {
    if (date.year < minYear || date.year > maxYear) {
      throw RangeError.value(date.year, 'date.year', 'Supported years are $minYear..$maxYear');
    }
    if (date.month < 1 || date.month > 12) {
      throw RangeError.value(date.month, 'date.month', 'Month must be 1..12');
    }
    if (date.day < 1 || date.day > 31) {
      throw RangeError.value(date.day, 'date.day', 'Day must be 1..31');
    }
    if (prayerIdx < 0 || prayerIdx > 4) {
      throw RangeError.value(prayerIdx, 'prayerIdx', 'Prayer index must be 0..4');
    }
    if (typeOffset < 0 || typeOffset > 9) {
      throw RangeError.value(typeOffset, 'typeOffset', 'Type offset must be 0..9');
    }

    final id = (date.year % 100) * 1000000 +
        date.month * 10000 +
        date.day * 100 +
        prayerIdx * 10 +
        typeOffset;

    if (id < minValidId || id > maxValidId) {
      throw StateError('Calculated ID $id is outside valid identity range ($minValidId..$maxValidId)');
    }
    if (reservedIds.contains(id)) {
      throw StateError('Calculated ID $id collides with a reserved system ID');
    }

    return id;
  }
}
```

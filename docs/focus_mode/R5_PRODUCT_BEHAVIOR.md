## 1. سيناريوهات المستخدم

### 1.1 الجدول الشامل للسيناريوهات

| # | السيناريو | الحالة | المدخل | الناتج المتوقع |
|---|---|---|---|---|
| S1 | تفعيل Focus Mode + بدء ورد الصباح في الموعد | الجلسة غير نشطة | AlarmManager يُطلق عند الموعد | يبدأ الـ Foreground Service، تظهر إشعار "جلسة التركيز نشطة" |
| S2 | المستخدم ينتقل إلى تطبيق مقيَّد أثناء الورد | الجلسة نشطة | polling كشف foreground app مقيَّد | يظهر Focus Shield Overlay خلال 1-5 ثوانٍ |

| S4 | المستخدم يكمل ورده بالكامل (شرط الاكتمال) | الجلسة نشطة | AzkarCompletionContract يُصدر حدث | تُنهى الجلسة، يُوقف الـ Foreground Service، يظهر إشعار تهنئة |
| S5 | المستخدم يضغط "إيقاف التركيز" يدوياً من الإشعار | الجلسة نشطة | نقرة على إجراء الإشعار | تُنهى الجلسة فوراً |
| S6 | الجهاز يُعاد تشغيله أثناء جلسة نشطة | — | BOOT_COMPLETED | استعادة الإعدادات، إعادة جدولة المنبهات، لا تُبدأ جلسة جديدة تلقائياً |
| S7 | الجهاز يُعاد تشغيله بين جلستين مجدولتين | — | BOOT_COMPLETED | إعادة جدولة المنبهات المستقبلية |
| S8 | Focus Mode مُعطَّل بالكامل | الميزة معطلة | — | لا شيء يحدث |
| S9 | Focus Mode مُفعَّل لكن لا يوجد ورد مُجدول اليوم | الميزة فعالة | — | لا جلسة تبدأ |
| S10 | المستخدم يبدأ ورده يدوياً (Activity-Based) | الجلسة غير نشطة | المستخدم يفتح شاشة الورد | ⚠️ OPEN QUESTION — انظر Q1 |
| S11 | المستخدم ينتقل بين تطبيقات مسموح بها | الجلسة نشطة | polling كشف تطبيق مسموح | لا يظهر Shield |
| S12 | يظهر اتصال هاتفي | الجلسة نشطة | Intent الهاتف | ⚠️ OPEN QUESTION — انظر Q2 |
| S13 | يمر الوقت المحدد للجلسة بدون إتمام | الجلسة نشطة | لا حدث اكتمال | ⚠️ OPEN QUESTION — انظر Q3 |
| S14 | التطبيق يُغلق بالكامل (killed from recents) | الجلسة نشطة | — | Foreground Service يستمر مستقلاً |
| S15 | PACKAGE_USAGE_STATS غير ممنوح | المستخدم يحاول تفعيل | — | يُعرض dialog يشرح الحاجة ويوجّه لـ Settings |

## 2. شروط الاكتمال (Completion Contracts)

### 2.1 الأذكار اليومية (أذكار الصباح / المساء)

**متى تُعتبر الجلسة مكتملة؟**

```
جلسة الصباح مكتملة إذا:
  - completedCount == azkarList.length للقسم "أذكار الصباح"
  - أي: كل ذكر تم تكراره العدد المطلوب (item.count)

المصدر: AzkarTrackerCubit.getZikrCount(text) >= item.count
```

**المشكلة:** هذا الشرط موجود فقط في Presentation layer.

**Contract المطلوب:**
```dart
// طبقة Domain — ملف جديد مقترح
abstract class AzkarCompletionPort {
  Stream<AzkarSessionResult> get completionEvents;
}

class AzkarSessionResult {
  final String category;    // 'أذكار الصباح', 'أذكار المساء', etc.
  final DateTime completedAt;
  final bool isFullyCompleted;
}
```

### 2.2 أذكار ما بعد الصلاة

**التعقيد:** لكل صلاة ورد منفصل (5 أوقات × 1 تصنيف = 5 جلسات يومياً محتملة).

**متى تُعتبر مكتملة؟**

> [!WARNING]
> **OPEN QUESTION (Q4):** هل إتمام ورد صلاة الفجر وحده يُنهي الجلسة؟ أم يجب إتمام كل الأوراد الخمسة؟ أم ورد صلاة واحدة على الأقل؟
>
> **انتظار قرار المستخدم.**

**الافتراض المبدئي:** كل ورد صلاة مستقل — إتمامه يُنهي جلسته الخاصة.

### 2.3 قراءة القرآن

> [!WARNING]
> **OPEN QUESTION (Q5):** ما الذي يعني "إتمام جلسة قراءة القرآن"؟
>
> الاحتمالات:
> - إغلاق تطبيق المصحف (غير كافٍ — المستخدم قد أغلقه بالخطأ)
> - قراءة عدد صفحات محدد (يتطلب تتبع دقيق)
> - قضاء مدة زمنية محددة في تطبيق المصحف (أبسط لكن قد لا يعني قراءة فعلية)
> - إنهاء السورة المحددة (يتطلب ربط مع حالة القرآن)
> - المستخدم يضغط زر "أنهيت" يدوياً (أكثر موثوقية)
>
> **انتظار قرار المستخدم.**

## 3. نموذج الإعدادات (Settings Model)

### 3.1 هيكل الإعدادات المقترح

```dart
class FocusModeSettings {
  final bool enabled;
  final Map<WardType, WardFocusConfig> wardConfigs;
}

class WardFocusConfig {
  final bool focusEnabled;        // هل التركيز مُفعَّل لهذا الورد
  final TimeOfDay? scheduledTime; // وقت الجدولة (null = يدوي فقط)
  final Set<int> activeDays;      // أيام الأسبوع (1=الاثنين, 7=الأحد)
  final Set<String> protectedApps; // package names للتطبيقات المحظورة
  final Set<String> exemptedApps;  // package names للتطبيقات المستثناة
}

enum WardType {
  morningAdhkar,   // أذكار الصباح
  eveningAdhkar,   // أذكار المساء
  postPrayer,      // أذكار بعد الصلاة
  quranReading,    // قراءة القرآن
}
```

| Messages / SMS | رسائل الطوارئ |
